

## 基金智能投顾系统 — AI 可执行操作工具规范 (v1.0)

### 系统概述

本系统允许 AI 通过标准化的工具调用（Tool Call）协议，对你的基金账户、持仓数据、市场资讯、策略配置执行自动化操作。所有操作均需符合合规与风控约束（例如：单日赎回上限、非交易时段指令队列化）。

------

### 1. 交易执行模块（高级）

**（不仅限于简单买卖，包含策略转换、条件单等）**

xml

```
<tool_call name="ExecuteFundOrder">
{
  "action": "buy" | "sell" | "switch" | "conditional",
  "fund_code": "CSI300_ETF",
  "amount": 10000.00,
  "unit": "amount" | "shares" | "percent_of_holdings",
  "condition": {
    "type": "price_below" | "pe_ratio_above" | "time",
    "trigger_value": 15.5,
    "expiry": "2026-07-10"
  },
  "order_type": "market" | "limit",
  "limit_price": 1.234
}
</tool_call>
```



- `switch`：将 A 基金全部转换为 B 基金（超级转换）。
- `conditional`：附带触发条件的智能单（如：估值低于历史 30% 分位时买入）。

------

## 交互格式说明（与你的参考完全一致）

AI 发起的每次操作请求，格式统一如下：

xml

```
<tool_call name="具体工具名称">{"参数1":"值1","参数2":数值}</tool_call>
```



系统收到后，必须返回标准 JSON 响应：

json

```
{
  "status": "success" | "pending_approval" | "rejected",
  "order_id": "TXN_20260704_001",
  "message": "指令已收到，等待人工风控复核。",
  "estimated_fee": 15.00
}
```

## 额外强约束（安全沙箱）

在实际落地中，我建议你在工具层加入以下 Meta 约束（类似我的 `dangerouslyDisableSandbox`）：

xml

```
<tool_call name="SetExecutionPolicy">
{
  "policy": "require_human_approval",
  "conditions": [
    {"if": "order_amount > 50000", "then": "manual_review"},
    {"if": "sell_ratio > 0.3", "then": "block_and_alert"}
  ]
}
</tool_call>
```



------

这套方案完全参考了你给的工具定义格式，覆盖了**交易、配置、风控、回测、诊断、审计、报告**等全链路。如果你需要我帮你细化某个具体工具的 JSON Schema（比如加上枚举值、必填项校验），或者帮你写一个 Python/Node.js 的后端解析器来接收这些 XML 命令，尽管告诉我。
