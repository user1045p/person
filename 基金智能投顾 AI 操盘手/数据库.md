### 🧠 核心底层判断逻辑（数据流向与业务规则）

这张设计图不是随意堆砌字段，而是严格遵循金融交易的生命周期。我为您拆解 **6 大核心判断逻辑**：

#### 1. 卖空限制 & 成本核算逻辑（`USER_POSITIONS` + `TRADE_ORDERS`）

- **判断步骤**：当 `ExecuteFundOrder` 的 `action=sell` 时，系统会执行 SQL：`SELECT available_shares FROM user_positions WHERE user_id=? AND fund_code=?`。
- **硬性否决**：若 `quantity > available_shares`，立即报错“可用份额不足”，绝不生成订单。
- **成本更新**：订单 `executed` 后，更新 `avg_cost = (旧总成本 + 新买入金额) / 新总份额`。赎回时按 `先进先出（FIFO）` 或 `加权平均`（这里用加权平均）计算赎回费，并联动写入 `CASH_TRANSACTIONS`。

#### 2. 金额防火墙与 T+1 时区逻辑（`TRADE_ORDERS` + `APPROVAL_TASKS`）

- **防火墙**：用户发起 `amount > 50000` 的买单或 `市值 > 50000` 的卖单，系统不会直接 `submitted`，而是写入 `order_status='pending_approval'`，并强制在 `APPROVAL_TASKS` 插入一条带 `expires_at`（15分钟）的记录。只有轮询发现 `approved`，才放行至报盘队列。
- **T+1 转换**：捕获系统时间（如 2026-07-04 15:30），若大于 15:00:00，则 `intended_date` 自动赋值为下一个交易日（跳过周六日）。UI 展示时明确提示“此订单将于 07-07（周一）参与集合竞价”。

#### 3. 行业集中度与相关性诊断（`FUND_SECTOR_TAGS` + `USER_POSITIONS`）

当调用 `AnalyzePortfolioHealth` 检查 `sector_concentration` 时：

- **逻辑**：将用户所有持仓的 `fund_code` 与 `FUND_SECTOR_TAGS` 表 JOIN，按 `sector_name` 分组，计算 `SUM(持仓市值 * weight_ratio)` / 总资产。
- **输出**：若单一行业（如“医疗”）占比 > 40%，触发“行业集中度偏高”预警，建议再平衡。

#### 4. 智能定投的估值倍数（`INVESTMENT_PLANS` + `FUND_NAV_HISTORY`）

调度器每日运行：

- **读取** `plan_status='active'` 且 `next_execute_date = today` 的计划。
- **获取** 当前 `pe_ttm` 与过去 5 年 PE 的百分位（通过 `FUND_NAV_HISTORY` 计算）。
- **倍数决策**：若 `pe_percentile < 30%`（低估），`multiplier=2.0`；30%-70% 为 `1.0`；>70% 为 `0.5`。最终扣款金额 = `fixed_amount * multiplier`，生成对应的 `TRADE_ORDERS`。

#### 5. 极端行情熔断（`MACRO_MARKET_DATA` + `RISK_GUARD_RULES`）

在生成任何买卖建议前，**优先查询**最新一条 `MACRO_MARKET_DATA`：

- 若 `fear_greed_index < 15` 或 `> 85`，系统在回复中强制插入 `⚠️ 极端情绪熔断警告`，并 **拒绝自动生成重仓单边指令**，直到读取到用户明确输入的特定指令（如“确认忽略贪婪信号”），该确认会记录在 `AUDIT_LOGS` 中以备合规审查。

#### 6. 再平衡的税费摩擦优化（`REBALANCE` + `TRADE_ORDERS` + `FUND_PRODUCTS`）

当调用 `RebalancePortfolio` 且 `consider_tax_impact=true` 时：

- **逻辑**：计算目标权重与当前权重的偏离。对于需要卖出的基金，查询 `FUND_PRODUCTS` 中的 `redemption_fee_rate`（持有时间越长费率越低）。
- **排序算法**：优先卖出**持有期超过 2 年（免赎回费）** 或 **偏离度最大** 的基金，以减少摩擦成本。生成的买卖清单会以“先卖后买”或“超级转换”形式写入 `TRADE_ORDERS`，并标记 `notes='再平衡调仓'`。

### 🗂️ 模块四：交易与资金流水（4 张表）— **最核心的交易链路**

#### 10. `trade_orders` — 交易委托主表（支持 T+1 与金额防火墙）

sql

```
CREATE TABLE trade_orders (
    order_id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id           INTEGER NOT NULL,
    fund_code         TEXT NOT NULL,
    action            TEXT CHECK(action IN ('buy','sell','switch','conditional_trigger')) NOT NULL,
    unit_type         TEXT CHECK(unit_type IN ('amount','shares','percent_of_holdings')) NOT NULL,
    quantity          REAL NOT NULL,                -- 对应金额(元)/份额(份)/百分比(%)
    order_type        TEXT CHECK(order_type IN ('market','limit')) DEFAULT 'market',
    limit_price       REAL,                         -- 限价单价格（仅 order_type='limit' 时有值）
    
    -- 状态机流转：draft -> pending_approval -> submitted -> (executed/failed/cancelled)
    order_status      TEXT CHECK(order_status IN ('draft','pending_approval','submitted','executed','failed','cancelled')) DEFAULT 'draft',
    
    request_time      TEXT DEFAULT (datetime('now', 'localtime')),
    intended_date     TEXT,                         -- 若15:00后，存下一个交易日（T+1）
    executed_time     TEXT,                         -- 实际撮合成交时间
    executed_price    REAL,                         -- 实际成交净值/价格
    fee               REAL DEFAULT 0,               -- 总手续费（申购/赎回费）
    notes             TEXT,                         -- 备注（如 "AI再平衡调仓"）
    
    approval_id       INTEGER,                      -- 关联大额审批表
    
    FOREIGN KEY (user_id) REFERENCES users(user_id),
    FOREIGN KEY (fund_code) REFERENCES fund_products(fund_code)
);
```

### 🔄 触发器（保证数据一致性，自动维护 `updated_at`）

在 SQLite 中，为 `user_accounts` 和 `user_positions` 添加自动更新时间戳触发器（避免应用层遗忘）：

sql

```
-- 用户账户更新时间触发器
CREATE TRIGGER update_user_accounts_timestamp 
AFTER UPDATE ON user_accounts
BEGIN
    UPDATE user_accounts SET updated_at = datetime('now', 'localtime') WHERE account_id = NEW.account_id;
END;

-- 持仓更新时间触发器
CREATE TRIGGER update_user_positions_timestamp 
AFTER UPDATE ON user_positions
BEGIN
    UPDATE user_positions SET updated_at = datetime('now', 'localtime') WHERE position_id = NEW.position_id;
END;
```
